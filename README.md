# 银行交易明细 PDF 重建工具（Agent Skill）

> 把「银行交易明细 CSV」按「原版对账单 PDF」的排版，重建为内容与 CSV **逐字段一致**的替换版 PDF。
> 适用于九江银行等使用固定网格模板打印的银行对账单；本仓库是其标准化 **Agent Skill**（AGENTSKILLS 格式），
> 附带可直接运行的 Python 脚本与全套质量校验。

---

## 一、背景：解决什么问题

银行信贷、授信审查等场景里，经常遇到两类文件：

1. **原版对账单 PDF** —— 排版漂亮、格式固定（标题 / 账户信息 / 十列流水网格 / logo / 防伪二维码），但往往**不含业务备注**，或流水与你手上的口径不一致；
2. **交易明细 CSV** —— 业务人员整理/补注后的口径（含「交易用途」等外部注释），但**没有排版**，无法直接作为正式材料。

本项目把两者的优点合二为一：**取原版 PDF 的版式骨架，取 CSV 的明细数据**，
生成一份「数据 = CSV、外观 = 原版」的替换版 PDF。整条流水线已沉淀为 skill 形式，
后续任意 agent（Claude Code / Codex / Cursor…）看到同样的任务都能稳定复现同一结果。

---

## 二、功能特性

- ✅ **版式与原版逐像素一致**：A4 网格、10 列等宽坐标、行距、表头带、红色标题、账户信息块全部来自对原版 PDF 的实测参数，并对每份输入做模板探测防漂移。
- ✅ **字体同源**：原版内嵌 TrueType STSong；本机 `STSONG.TTF`（华文宋体）与其**度量逐字符一致、字形像素一致**，按需子集化嵌入，PDF 体积小且离线可渲染。
- ✅ **图文资源自动提取**：首页 logo、右上防伪二维码（含透明通道、按原版 z 序叠放）从原版 PDF 自动定位并复用。
- ✅ **数据完整性与健壮性**：
  - 自动修复 Excel 另存导致的 CSV 损坏（见下表）；
  - 支持「交易时间秒数为 00 → 随机 01–59」的批注化处理；
  - 金额支持千分位 / 符号差异；
  - 汇总头与逐行重算不一致时告警。
- ✅ **像素级质量验证**：内容回读、几何坐标、网格像素、静态区与原版对比四层校验，输出 PASS/FAIL 清单。
- ✅ **中文注释、可直接运行**：脚本零外部配置，仅依赖 `pymupdf / fonttools / Pillow`。

## 五、快速开始

### 5.1 生成替换版 PDF

```bash
python scripts/make_statement.py "<交易明细.csv>" "<原版对账单.pdf>" "[输出.pdf]"
```

- 参数一：明细 CSV（UTF-8，可带 BOM）；前若干行是键值头（查询账号 / 开户银行 / 账户名称 / 交易时间范围 / 借贷汇总），其后是列表头 `交易时间,交易金额,收入,支出,余额,币种,对方账号,对方户名,摘要,交易用途`。
- 参数二：原版对账单 PDF（作为版式模板与图像来源）。
- 参数三（可选）：输出路径；缺省为 CSV 同目录 `<原版名>-明细按CSV替换版.pdf`。

示例：

```bash
python scripts/make_statement.py "2025年版_九江银行交易明细清单.csv" "交易明细清单-2025.5.1-2025.12.31.pdf"
# => 交易明细清单-2025.5.1-2025.12.31-明细按CSV替换版.pdf（3 页 59 笔）
```

### 5.2 验证

```bash
python scripts/verify_statement.py "<明细.csv>" "<原版.pdf>" "<输出.pdf>"
```

输出 `OVERALL: OK` 才视为合格；任何 FAIL 都会指明是哪一层（内容 / 几何 / 网格 / 像素）。

### 5.3 随机秒（按需）

```bash
python scripts/randomize_seconds.py "<明细.csv>"   # 原位覆盖
python scripts/randomize_seconds.py "<明细.csv>" "<输出.csv>"
```

仅当用户要求「交易时间秒数不要整点 00、改成随机秒」时使用；只替换时间字段的秒位子串，**绝不动行尾其他字段**。

## 六、工作原理（关键参数均来自实测）

### 6.1 版式参数速查（九江银行模板实测值）

| 项 | 值 |
|---|---|
| 页面 | A4 595×842 |
| 表格 | 10 等宽列，x = 36.0, 88.3, 140.6, …, 506.7, 559.0（列宽 52.3） |
| 首页表头带 | 顶线 y=133.8；表头文字基线 145；首数据行顶 146.8 |
| 续页 | 表格顶线 35.8，无表头，行直接续排 |
| 行高 | `max(30, 9 × 行内文本行数 + 4)`；行内行距 9.0；首行基线 = 行顶 + 11.5 |
| 对齐 | 金额/收支/余额右对齐（右缘 = 列右界 − 2.0pt）；其余列逐行居中 |
| 折行 | 账号/户名/摘要/用途按可用宽 49.5pt 贪心逐字折行（STSong 下 ≈11 位数字 / 5 个汉字一行） |
| 标题 | 「交易明细清单」红 #FF0000，20pt，居中 |
| 网格线 | 黑色 0.5pt 描边，随内容收底（末页边框停在最后一行下沿） |
| logo | 首页左上 (41,37,159,67) |
| 二维码 | 每页右上 (450,44.4,540,132)，画在行文字之上（模块像素才覆盖，透明区不遮字） |

生成前脚本会对每份原版 PDF 首页做**像素模板探测**（前两条网格线必须 ≈133.8 / 146.8），不符即报错，防止换模板后静默错排。

### 6.2 字体说明

- 原版 PDF 内嵌 **STSong** 子集（TrueType）。系统 `C:\Windows\Fonts\STSONG.TTF`（华文宋体）与其**度量逐字符一致**（如 `2025-05-01` 宽度 39.40pt、11 位账号 46.43pt、`人民币` 27.0pt），渲染像素一致。
- 生成器以 STSONG 为母体，按「全部将写入文本的字符集」做 **fontTools 子集化**后嵌入，字体文件小、离线可渲染、无豆腐块。
- 若运行机无 STSONG，可改用 `simsun.ttc` 等宋体，但静态区与原版像素对比会退化为「字形近似」（几何仍精确）。

### 6.3 分页与容量

首页数据行容量 ≈ 21 行、续页 ≈ 25 行（30pt 行时）；行内文本超过 2 行时行自动加高，翻页随之自然发生；最后一页边框收在内容底边，与原版行为一致。

## 七、CSV 健壮性处理（Excel 另存的常见损坏）

业务人员常用 Excel 编辑 CSV 再另存，会产生**不可逆**损坏。skill 内置修复规则：

| 症状 | 成因 | 处理 |
|---|---|---|
| `2025/5/1 10:15`（斜杠 / 去零 / 丢秒） | Excel 日期格式 | 与基线对齐，恢复 `2025-05-01 10:15:20` |
| `对方账号` 变 `6.217E+18`、`9.91521E+15` | 长数字自动科学计数，**低位丢失** | 按行从旧数据基线恢复原文 |
| 键值头「查询账号」变科学计数 | 同上 | 从原版 PDF 首页文本恢复 |
| 金额丢 `+`、丢尾零 | 数字单元格 | 数值无损，格式化由生成器补回 |
| 时间秒全为 `00` | 录入习惯 | 按需随机化为 01–59 |

> 修复原则：**只覆盖可疑字段，绝不整行重写**；当用户声明「只改了某一列」时，其余列与基线逐行比对，差异全部打印出来供人工确认。

## 八、验证标准（四层，全 PASS 才算完成）

| 层 | 检查项 |
|---|---|
| 内容 | PDF 文本层含全部日期 / 时间 / 金额（千分位）值，无缺无重 |
| 几何 | 首页首行基线 ≈158.3；金额右缘 = 138.6 / 190.9 / 243.2 / 295.5（±0.3pt） |
| 网格 | 首页表头带 133.8/146.8、续页顶线 35.8、列分隔线 ≥ 11 条 |
| 像素 | 与原版静态区（logo/标题/账户信息/表头）对比：logo 0.0%、背景 <0.5%、顶部 <12%、表头 <30%（残余为表格线 0.05pt 亚像素差） |

另有两条手工强校验：**逐行回读比对**（按列坐标把 PDF 行拼回 10 字段，与 CSV 逐行比较，要求 0 不一致）、随机秒后要求 CSV 与 PDF 均无 `:00`。

## 九、已知坑与注意事项

1. **覆盖被占用文件**：目标 PDF 被查看器打开会 `PermissionError`；请先关闭，或改用临时文件 + `os.replace`。
2. **只改目标子串**：编辑/修复 CSV 时勿把整行替换掉（曾有整行覆盖导致 8 行数据丢失的事故）。
3. **千分位金额**：合并/修复产物可能带 `,`，解析时先 `replace(',', '')`。
4. **子集字体字符集**：务必覆盖标题、信息块、表头与每行每列完整字符串及 ASCII 标点，漏字符会出现「豆腐块」。
5. **行锚回读**：PDF 多行折行的账号/摘要/用途需按列坐标区间拼接，不能按页面顺序直拼。
